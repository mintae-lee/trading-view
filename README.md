# trading-view

TradingView Pine Script(v6) 주식 차트 분석 지표 모음.
역배열 바닥권에서 반등 시점을 잡는 매매 기법들을 지표로 구현한 것.

## 파일 구성

```

├── Reverse112.pine         역매공파BB_112   — 이전 버전(일반 BB). 보관용
├── ConcreteThrough.pine    하락후지지 돌파
├── BowlNo3_256.pine        1년밥그릇256기법 — 256(5·20·60) 주 신호 + 밥그릇 3번 흔들기 보조
├── Return5days.pine        5일하락 후 장대양봉 돌파
```

## 사용법

각 `.pine` 파일 내용을 TradingView 차트의 **Pine 에디터**에 붙여넣고 "차트에 추가".
지표 설정창에서 기간·배수 등 주요 파라미터를 조정할 수 있다.

전부 `indicator()` 기반이라 **신호를 시각화할 뿐 백테스트(승률/손익비)는 계산하지 않는다.**
`strategy()`로 변환하면 Strategy Tester에서 수치 검증이 가능하다.

## 로컬 검증 (tools/bowl_check.py)

Pine 런타임은 로컬에 없다 — TradingView 서버에서만 도는 폐쇄형 언어라 **문법 검증은
Pine 에디터에 붙여넣는 수밖에 없다.** 다만 신호 빈도나 파라미터 기본값 같은 *로직*
문제는 파이썬으로 같은 계산을 재현해 확인할 수 있다.

`tools/bowl_check.py`가 `BowlNo3_256.pine`의 로직을 봉 단위로 다시 구현한 것이다.
표준 라이브러리만 쓰므로 설치가 필요 없다.

```bash
# 데이터 없이 로직 자가 검증 (정답을 아는 합성 밥그릇으로 회귀 확인)
python3 tools/bowl_check.py --selftest

# 실제 데이터: TradingView 차트 → 우상단 메뉴 → "Export chart data..." → CSV
python3 tools/bowl_check.py data/*.csv

# minAccumBars × accumRatio 격자를 훑어 기본값 후보 찾기
python3 tools/bowl_check.py data/*.csv --sweep
```

장기선(224) 계산에 최소 284봉이 필요하므로 CSV는 넉넉히(2년 이상) 내보낼 것.

⚠️ 이건 **Pine 코드 자체가 아니라 로직 설계의 검증**이다. 두 구현이 갈라질 수 있으니
출력된 신호 날짜는 차트와 대조해야 한다.

## 이평선 기간에 대한 메모

**112 / 224 / 448 을 쓴다. 미국주식도 동일하다.** 특정 유튜버("남현")의 커스텀
설정으로 공인된 표준은 아니며, 각각 약 **5.5개월 / 11개월 / 22개월**에 해당한다.
전부 `input` 이므로 종목에 따라 설정창에서 바꿀 수 있다.

### 미국 관행값 50/200 으로 바꾸지 않는 이유

미국의 표준은 50일·200일이지만 이 기법에는 맞지 않는다. 관행값이 작동하는 근거는
**반사성**(많은 참여자가 보니까 그 가격에서 반응한다)인 반면, 이 기법이 224를 쓰는
근거는 **"1년치 매물대"라는 원가 논리**다. 논리가 다르므로 숫자만 가져다 쓰면 안 된다.
특히 미국 50일선은 2.4개월짜리라 중기(5.5개월)의 절반도 안 되며, 역할상 한국
60일선(3개월)에 가깝다.

### 거래일 환산(115/230/461)도 하지 않는 이유

한때 `252/245 = 1.0286` 을 곱해 115/230/461 로 바꿨다가 되돌렸다. 가짜 정밀도였다.

- 연간 거래일이 미국 250~253 / 한국 246~248 로 거의 같아 **보정폭이 3봉뿐인데,
  계수 자체의 불확실성(1.008~1.028)이 그 보정폭과 맞먹는다.**
- 합성 데이터 측정 결과 **MA112 와 MA115 의 값 차이는 중앙값 0.19%**, 역배열 판정이
  뒤집히는 봉은 **2.25%** 에 불과했다. 사실상 같은 선이다.
- 112/224/448 은 애초에 `112 × {1,2,4}` 인 어림값이다(224 거래일은 11개월이지
  1년이 아닌데도 "1년선"이라 부른다). 어림값에 유효숫자 3자리 환산은 무의미하다.
- 115일선·461일선을 보는 참여자는 **아무도 없어** 반사성 이점도 0이다.

### 아직 답하지 못한 질문

**미국 종목에서 200선과 224선 중 어느 쪽이 실제로 지지·저항으로 작동하는가**는
추측이 아니라 측정 대상이다. 실데이터 CSV 로 두 설정을 각각 돌려 신호 수와 이후
성과를 비교해야 답이 나온다.

## 검증이 필요한 항목

- **BowlNo3_256 (256 재도입)** — 한때 매수 자리를 3번(돌파 후 눌림)으로 옮기며 256
  신호(골든크로스)를 제거했었다. 256 이미지 기준으로 다시 **256 을 주 신호**로 두고,
  밥그릇은 "256 을 쓸 자리(2번 끝단부)"를 정하는 틀로 쓴다. 2번 관찰 신호(흰 삼각형)는
  256 과 겹쳐 제거했다. 이 과정에서 **하락 지속 판정 버그**를 고쳤다 — 바닥 위에서
  5% 넘게 되밀린 쌍바닥도 "아직 하락 중"으로 보고 매집 기간을 0으로 리셋해, 정상 256
  패턴의 BUY 가 합성 0/10 이었다(수정 후 10/10). 중장기 모드(5/112/224)는 평평한 바닥에서
  5일선이 112선을 오르내려 손절이 잦다(합성 5/10 만 224 돌파까지 이어짐).
- **BowlNo3_256 파라미터** — 합성 데이터 기준으로 `volWindow=10` / `volMult=1.5`
  일 때 탐지율 75%, 오탐 0.05건/1000봉. 오탐을 막는 건 거래량이 아니라 매집 길이·
  비율 조건이었다. 다만 합성 노이즈는 실제 차트의 "실패한 밥그릇"을 재현하지 못하므로
  **오탐률은 낙관적으로 추정된 값**이다. 실데이터 CSV로 재확인 필요.
- **BowlNo3_256 흔들기 수정** — 수정 전에는 3번 "흔들기"를 실제로 확인하지 않았다.
  돌파 직후엔 주가가 이미 224선 +3% 안에 있어 첫 양봉이 곧바로 눌림으로 잡혔고,
  합성 검증에서 **23/23건이 돌파 다음 봉에 BUY** 였다. 이제는 224선 위로
  `minRunupPct`(10%) 이상 올라간 뒤 되밀려야 인정한다(합성 기준 돌파 후 18~21봉).
  함께 `minAccumBars` 30→80(이미지의 "매집 최소 4개월"), 1번 최소 낙폭 30% 조건,
  4번 +50%/+100% 목표선을 넣었다. 위 탐지율·오탐 수치는 **수정 전 기본값 기준**이라
  실데이터 CSV 로 다시 재야 한다 (`--sweep` 으로 매집 길이 격자 비교 가능).
- **하락후지지 돌파 (공구리)** — 수정 전에는 언덕 **돌파 봉**에 "Concrete" 를 찍었다.
  이미지 기준 공구리는 돌파 후 되밀릴 때 언덕이 지지되는 것이라, 되밀려 언덕을 뚫고
  내려가는 실패한 돌파에도 신호가 붙었다. 지지선도 언덕이 아니라 돌파봉 시가에
  그어졌다. 이제 2단계(돌파 → 지지 확인)로 나누고, 고점 하락(하락 박스)·엘리엇 1파
  모드를 넣었다. `tools/concrete_check.py --selftest` 로 합성 패턴은 통과하지만
  실제 차트 신호 빈도는 아직 안 쟀다.
- **MaHit (이평때리기)** — "많이 빠졌던" 판정을 "최근 60봉 112선 대비 -10% 이격"에서
  "최근 250봉 448선 대비 -35% 이격"으로 바꿨다. 예전 조건은 바닥이 길면 EMA112 가
  주가에 붙어버려 이미지처럼 긴 바닥 뒤의 돌파가 **전부 탈락**했다(합성 바닥 200·300봉
  0/20). 이미지의 두 번째 화살표(224선 때린 뒤 224선 안착 → 448 도전)도 `224↑` 로
  추가했다. `tools/mahit_check.py --selftest` 통과, 실데이터 빈도는 아직 안 쟀다.
- **112지지매집** — 사양서 기준으로 전면 재작성했으나 실제 차트에서 신호 빈도를
  확인하지 않았다. `useDisplacedBB` 토글로 켈트너채널 대신 26봉 선행이동 BB를
  써볼 수 있다. 그래서 아직 `pending/`에 있다.
